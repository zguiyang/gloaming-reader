# Gloaming MVP 端到端测试指南

**文档性质：** 面向人工测试（Chrome 可视化操作）的正式 MVP E2E 指南。

**依据：** 当前仓库实现与 [`docs/product/mvp-scope.md`](../product/mvp-scope.md)、[`docs/product/mvp-1-modules.md`](../product/mvp-1-modules.md)、[`docs/product/prototype-flows.md`](../product/prototype-flows.md)、[`docs/product/feature-audit.md`](../product/feature-audit.md)、[`docs/deployment.md`](../deployment.md)。
**非依据：** 路线图 Phase 1b（用户上传）、Practice/Review/SRS、独立搜索页等未实现或未纳入 MVP 1 学习者能力。

**版本：** 与当前仓库行为对齐（ReadingWork 域、Catalog EPUB 供应、手动工作流 + Worker 队列）。

**当前路径（2026-09-28）：** Admin Catalog 使用 `/admin/catalog/works` 和 `/api/admin/catalog/works`，音频 API 也以 Catalog Work 为路径范围。Personal EPUB 已有认证 API `POST /api/works`；本指南仍不把它列为浏览器 UI E2E 能力，因为当前没有学习者上传界面。下方较早日期的验收记录保留当时实际访问的旧路径。

## 1. 测试目标与范围

### 1.1 目标

在**真实浏览器**中，以**新注册学习者**与**管理员**两种身份，验证 MVP 1a 主链路是否可用：

1. 认证与会话（含邮箱验证、重发验证邮件、密码找回；**GitHub OAuth 不计入本轮必测分母**，见 §1.6）。
2. 学习者 IA：**我的书架** / **发现** / **阅读历史** → 作品详情 → **Reader**。
3. Reader 内：章节导航、进度同步、阅读心跳、完成/重启、并发 revision 冲突恢复。
4. 阅读辅助：TTS（美式/英式）、词典、翻译（SSE）、AI 助手（流式 + 对话历史）。
5. 账号与退出；管理员 EPUB 供应链、资源扫描/清理、分类/标签/来源、AI/TTS/词典配置与日志。

### 1.2 范围内（必须覆盖）

| 能力                                          | 学习者 UI        | 管理员 UI |
| --------------------------------------------- | ---------------- | --------- |
| 官方目录阅读                                  | 是               | —         |
| Admin EPUB 上传 → 解析 → 元数据 → 音频 → 发布 | —                | 是        |
| Better Auth 会话                              | 是               | 是        |
| Worker 异步任务（解析、TTS、资源清理等）      | 间接（等待状态） | 是        |

### 1.3 范围外（不得当作 MVP 学习者功能测试）

| 排除项                                   | 说明                                                                                                               |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **用户上传 / 导入 UI**                   | 当前没有学习者界面；Personal EPUB API 的自动化验收不属于本指南的浏览器 UI 用例                                     |
| **Practice / Review / SRS / 测验**       | 已从代码库移除                                                                                                     |
| **`admin_text` 创建路径**                | 内部 dev/test/seed（如 `seed:dev`），**不是**产品 EPUB 供应流程；学习者只见已发布作品                              |
| **独立「搜索」页**                       | 产品未设独立 Search 模块；发现页 UI 为**分类 + 标签**筛选（后端 catalog API 支持 `q`，当前发现页**无**标题搜索框） |
| **Short Article Library / Article 模型** | 已归档，勿测                                                                                                       |

### 1.4 用例分类图例

| 标记             | 含义                                                    | 失败处理                                                   |
| ---------------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| **【必须通过】** | MVP 发布门禁；环境齐全时必须 PASS                       | 记 **FAIL**，提缺陷                                        |
| **【环境依赖】** | 依赖邮件 / LLM / Azure TTS / S3 / GitHub OAuth / Worker | 环境未就绪 → **BLOCKED**（见 §2.5），**不得**记为产品 FAIL |
| **【可选分支】** | 有价值但非全员环境具备                                  | 未测记 **SKIP** 或 **BLOCKED**                             |
| **【未实现】**   | 代码或产品明确不在 MVP                                  | 不执行；若 UI 误出现则记 **FAIL**                          |

### 1.5 验证分层（勿混淆）

本指南区分三类证据，**不得**把后端 Vitest 通过记作「Chrome E2E 已通过」。

| 分层           | 含义                                                                  | 典型证据                                 |
| -------------- | --------------------------------------------------------------------- | ---------------------------------------- |
| **浏览器 E2E** | 测试人员在 Chrome 中按步骤操作 UI，观察页面/Network/Cookie            | 截图、HAR、URL、Toast 文案               |
| **后端自动化** | `apps/backend/tests/**` 内 functional/unit 对 Hono API 或域逻辑的断言 | Vitest 报告、`*.spec.ts` 用例名、CI 日志 |
| **未验证**     | 本轮无浏览器记录，且仓库无对应自动化覆盖（或仅覆盖 API 子集）         | 记 **NOT_RUN**；禁止虚构浏览器步骤       |

单条用例可同时具备「浏览器 E2E（主验收）」与「后端自动化（辅证）」；**发布门禁以浏览器 E2E 的【必须通过】项为准**，后端自动化仅作回归参考，见 §21 矩阵。

### 1.6 结果状态与覆盖率

**结果状态（每条用例必填其一）：**

| 状态        | 含义                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| **PASS**    | 浏览器 E2E 步骤已执行且全部预期满足                                     |
| **PARTIAL** | 已执行但仅部分预期满足，或仅 API/后端自动化通过、**未**完成 Chrome 复测 |
| **FAIL**    | 已执行且与预期不符（非环境误报）                                        |
| **BLOCKED** | 环境/依赖未就绪，无法执行（§2.5）                                       |
| **SKIP**    | 本轮主动跳过（含约定不测项）                                            |
| **NOT_RUN** | 本轮尚未执行且无有效浏览器证据                                          |

**覆盖率计算（MVP 门禁）：**

```text
分母 = 全部用例 ID − GitHub OAuth（E2E-AUTH-006）− 明确标为【未实现】的项 − 可选仅 API 项（E2E-DSC-003，若标 SKIP）
通过数 = 分母内状态为 PASS 的条数
覆盖率 = 通过数 / 分母 × 100%
```

- **NOT_RUN、BLOCKED、SKIP、PARTIAL、FAIL** 均**不计入**通过数。
- **PARTIAL** 不得当作完整通过；需复测至 PASS 或记 FAIL。
- **E2E-AUTH-006（GitHub）**：用户后续自行验证；**不计入分母**；若测则单独记录，不影响上述覆盖率。

**【必须通过】子集：** 凡表头含 **【必须通过】** 的用例，发布前应在环境齐全时达到 **PASS**（或已修复的 FAIL），不得以 BLOCKED 长期替代而不记录。

### 1.7 单条用例记录字段

除下文各节表格外，执行时同步填写 §21 矩阵。每条用例固定字段：

| 字段             | 说明                                                          |
| ---------------- | ------------------------------------------------------------- |
| **ID**           | 全局唯一，如 `E2E-AUTH-001`                                   |
| **前置**         | 账号、数据、环境依赖                                          |
| **操作**         | Chrome 可逐步执行的步骤（勿写未做过的操作）                   |
| **预期**         | 可观察的 UI/API/Cookie 结果                                   |
| **证据**         | 应收集的截图/Network/邮件等                                   |
| **数据清理**     | §3.2                                                          |
| **验证分层**     | 浏览器 E2E / ± 后端自动化                                     |
| **结果状态**     | §1.6                                                          |
| **本轮当前证据** | 如「无」、`auth.spec.ts: …`、截图路径；**无执行则写 NOT_RUN** |

### 2.5 环境未配置时如何标记 BLOCKED

在测试结果中填写：

```text
结果：BLOCKED
原因：<缺失依赖，如 Worker 未运行 / 未配置 RESEND / 未配置 LLM>
复现条件：环境补齐后可执行 <用例 ID>
是否产品缺陷：否
```

## 3. 数据准备与清理规则

### 3.1 准备（推荐顺序）

1. 确认 §2.1 服务与健康检查。
2. 创建或确认**管理员**存在。
3. （可选）运行 `seed:dev` 仅用于快速学习者冒烟；**EPUB 管理员用例仍须单独上传 EPUB**。
4. 管理员上传并**发布**至少 1 部 EPUB 作品（含多章节更佳），供学习者发现/书架/Reader 深度测试。
5. 准备第二个 Chrome Profile 或隐身窗口，用于「并发冲突」场景。

### 3.2 清理原则

| 对象             | 建议                                                                     |
| ---------------- | ------------------------------------------------------------------------ |
| 测试学习者账号   | 测试周期结束后由运维删除 `user` 行或保留隔离环境；**勿**在生产库清理     |
| 测试 EPUB 作品   | 管理员后台 **取消发布** → **删除作品**（若 UI 提供）；避免污染他人发现页 |
| 邮箱             | 使用 `+tag` 别名（如 `qa+20260922@domain.com`）便于识别                  |
| 对象存储孤儿文件 | 仅通过管理员 **资源扫描/清理** 流程处理；测试人员**不要**手删 bucket     |

### 3.3 专用测试环境

优先使用**独立**部署或本地 Docker Compose，**禁止**对生产数据执行本指南中的 destructive 操作。


## 6. 认证：注册、验证、重发、登录、未验证、忘记密码、改密相关

> **GitHub OAuth（E2E-AUTH-006）** 见 §6 末：用户后续自行验证，**不计覆盖率分母**。

**实现要点（与代码对齐，测试以 UI/Network/Cookie 为准）：**

- 登录弹窗/页：`login` 单字段支持**邮箱或用户名** + 密码（非邮箱格式时走 `signIn.username`）。
- 弹窗内登录成功：`refresh` 会话后 `router.replace(consumePostAuthPath())`，默认 **`/my-shelf`**，或 URL `returnTo`/`returnPath`、或 `sessionStorage` 中记住的路径。
- 注册验证：邮件链直达 **`/verify-email?token=…`**；页面用 **JSON** 调 `GET /api/auth/verify-email`（非浏览器跟随 302）；成功态需**点击**「前往书架」才跳转；当前后端**未**配置 `autoSignInAfterVerification`，验证成功**通常不会**自动写入会话 Cookie——无 Cookie 时须再走 AUTH-003 登录。
- 重置密码：提交成功后 `replace(consumePostAuthPath())`；Better Auth **reset-password 不创建会话**，且 `revokeSessionsOnPasswordReset: true` 会撤销旧会话——跳转后若无 Cookie，以登录弹窗/401 为准，再用新密码登录。

**【必须通过】E2E-AUTH-001 — 邮箱注册**

| 项                   | 内容                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------- |
| **前置**             | 未使用过的邮箱；邮件服务可用                                                              |
| **步骤**             | Landing 或 Auth 弹窗 → 注册：姓名、用户名、邮箱、密码 → 提交                              |
| **预期**             | 成功提示「查收邮件」；未自动完成登录（硬验证策略）                                        |
| **证据**             | 注册成功 UI、Network `POST /api/auth/sign-up/email` 200                                   |
| **清理**             | 记录邮箱供验证用例                                                                        |
| **验证分层**         | 浏览器 E2E；辅证：`apps/backend/tests/functional/routes/auth.spec.ts`（注册 + 默认 role） |
| **结果状态（本轮）** | PASS                                                                                      |
| **本轮当前证据**     | 2026-09-24 学习者：新注册成功（§22H）。早前轮次：临时未验证账号注册成功，页显「再发一次」 |

**【环境依赖】E2E-AUTH-002 — 邮箱验证成功**

| 项                   | 内容                                                                                                                                                                                                                                     |
